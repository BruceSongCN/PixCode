# 多目标交付

## Target

Target 表示一个可独立实现和验证的交付目标，例如后端服务、Web、移动端、监控大屏或集成层。Target 名称由当前变更和实际代码库确定，不在通用框架中预置技术栈。

## 边界

- proposal 必须列出受影响 Target 和各自责任。
- 共享契约必须标出提供方、消费者、兼容方式和发布顺序。
- tasks 按独立仓库拆分，跨仓改动不视为原子提交。
- 每个 Target 分别读取仓库规则、检查状态、构建和测试。
- 跨 Target 场景由协调者维护共享设计和最终结论；单 Target 实现不得自行改变共享契约。

## 增量适配

框架不保存 ABP、Umi 或其他具体技术栈 Adapter。项目特有的构建命令、目录、运行方式和测试 Provider 放在对应代码仓库或项目安装层，只有被当前 Target 使用时才读取。
